# Оптимизация складских запасов и ABC-анализ ассортимента

**Ссылка на скрипт с кодом:** [queries.sql](queries.sql)

**Компания:** Global Foods & Beverages

## Цель проекта
Провести сегментацию товарного ассортимента по вкладу в выручку, выявить критические точки дефицита хитовых позиций и неликвидных товаров, оценить эффективность поставщиков и создать витрину данных для дальнейшего использования в BI-системах с целью максимизации выручки.

## Описание проекта
Выполнен комплексный исследовательский анализ данных (EDA) реляционной базы данных компании. В рамках проекта решены 4 ключевые бизнес-задачи с помощью продвинутых возможностей SQL:

1. **ABC-анализ ассортимента:** Сегментация товаров по принципу Парето (80/20) с использованием оконных функций для расчета кумулятивной доли выручки.
2. **Поиск дефицита и неликвида:** Выявление товаров категории «А» с нулевым складским остатком (упущенная выгода) и товаров без продаж (мертвый груз) через паттерн `LEFT JOIN ... IS NULL`.
3. **Рейтинг поставщиков и анализ трендов:** Ранжирование поставщиков по выручке от хитовых товаров (`DENSE_RANK()`) и расчет скользящего среднего продаж топ-товара для сглаживания сезонности (`AVG() OVER(ROWS BETWEEN...)`).
4. **Создание витрины данных (Data Mart):** Сохранение результатов ABC-анализа в отдельную таблицу (`CREATE TABLE AS SELECT`) для подключения BI-инструментов без повторных тяжелых вычислений.

## ️Технические особенности реализации
- **Многошаговая логика через CTE (`WITH`):** Декомпозиция сложных расчетов на читаемые блоки вместо вложенных подзапросов («матрешек»).
- **Оконные функции без схлопывания строк:**
  - `SUM() OVER()` — расчет кумулятивной доли выручки для ABC-анализа.
  - `DENSE_RANK() OVER()` — плотное ранжирование поставщиков без разрывов в местах.
  - `AVG() OVER(ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)` — скользящее среднее за 3 периода для сглаживания сезонных колебаний.
- **Паттерн `LEFT JOIN ... IS NULL`:** Моделирование оператора `EXCEPT` для поиска разрывов между таблицей продаж и складских остатков.
- **Работа с типами данных:** Приведение к `::numeric` для избежания ловушки целочисленного деления при расчете долей, округление через `ROUND()`, форматирование дат через `to_char()`.
- **DDL для создания витрины:** Использование `CREATE TABLE AS` для сохранения результатов в отдельную таблицу.
